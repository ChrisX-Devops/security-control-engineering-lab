# Frameworks

This folder contains the conceptual foundation documents
that govern how I think about and position my work.

These documents are not project deliverables. They are
the mental models that shape every project deliverable.

## Documents

### instrumentation-context.md
Maps every project in this portfolio to control system
components. Documents how my security work mirrors
industrial control system patterns at a conceptual level.

### honest-positioning.md
Explicit statement of what I can and cannot claim. The
guardrail document that prevents overclaiming during
sales calls and interviews.

### soc2-iec62443-crosswalk.md
Conceptual mapping between SOC2 Trust Service Criteria
and IEC 62443 Foundational Requirements. Demonstrates
framework awareness without claiming OT assessment
capability.

## Why These Documents Exist

Technical work without conceptual foundation is just code.
Conceptual foundation without honest positioning is risky.

These documents ensure:
- Every claim I make is defensible
- Every system I build has clear conceptual roots
- Every commercial conversation respects the boundary
  between what I have proven and what I am building toward

## Update Cadence

These documents update when:
- New capabilities are proven (positioning expands)
- New frameworks become relevant (crosswalks expand)
- New control system concepts are applied (instrumentation
  context grows)

The goal is honest expansion, not aspirational claims.
